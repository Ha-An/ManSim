# ManSim v0.6 Release Notes

ManSim v0.6은 다중 휴머노이드의 제조 task dispatch를 재현 가능하게 비교하기 위한 릴리스입니다.
핵심 범위는 병렬 설비와 유한 버퍼를 갖는 `mfg_flow_shop`, 시나리오별 확률 timing, 엄격한
주기형 Rolling Horizon, Simulation-Based ADP 학습 및 held-out 정책 비교입니다.

## Release Identity

- 현재 코드 버전은 `0.6.0`입니다.
- 제조 및 조선 run은 `run_meta.json`의 `mansim_version`에 실행 버전을 기록합니다.
- ADP checkpoint manifest와 `training_summary.json`에도 학습에 사용한 ManSim 버전을 기록합니다.
- HumanoidSim은 task/primitive 구조와 난이도를 소유하고 ManSim은 시나리오별 실행시간과 domain
  transition을 소유합니다.

## Manufacturing Model

- `mfg_flow_shop`의 Station 1과 Station 2는 각각 병렬 설비 2대를 사용합니다.
- Station 1 가공시간은 triangular `7/8.5/11분`, Station 2는 `10/12.5/16분`입니다.
- Station 및 Inspection queue에는 점유량과 inbound reservation을 함께 제한하는 finite capacity를
  적용합니다. 가공 완료 후 output buffer가 가득 차면 item은 machine 안에 남고 설비는 blocked됩니다.
- Inspection을 desk load, stationary inspection, desk unload의 독립 task로 분리했습니다.
- Worker는 전용 charging dock에서 직접 충전하며 machine repair만 공동 작업으로 허용합니다.
- `minimize_makespan`은 초기 material lineage가 product 또는 최종 scrap으로 모두 종결되면 종료하고,
  `maximize_throughput`은 매일 material을 보충하며 설정 horizon까지 실행합니다.

## Dispatch Policies

`mfg_flow_shop`의 규칙 기반 비교는 dispatch 시점과 역할 독점 여부를 분리한 네 정책을 사용합니다.

| Policy | Decision timing | Role ownership | 목적 |
| --- | --- | --- | --- |
| `immediate_shared` | worker idle event | shared | 즉시 반응형 기준선 |
| `immediate_dedicated_roles` | worker idle event | exclusive role 1-16 | 역할 분리 효과 측정 |
| `rolling_horizon_shared` | strict periodic boundary | shared | 주기형 재계획 효과 측정 |
| `rolling_horizon_dedicated_roles` | strict periodic boundary | exclusive role 1-16 | 주기형 재계획과 역할 분리의 결합 |

Rolling 정책은 worker polling에 의존하지 않습니다. 독립 SimPy coordinator가 정확한 window 경계에서
미시작 queue를 회수하고 후보를 재검증해 전체 재할당합니다. 실행 중 task는 선점하지 않으며
low-battery self-charge만 현재 task 다음에 긴급 삽입됩니다.

역할 체계는 16개 생산·inspection 세부 역할, 모든 worker의 self-service power 역할, 공동 repair
역할로 구성됩니다. Dedicated 정책은 예상 발생 횟수와 task busy time을 이용한 deterministic LPT로
exclusive 역할을 한 번 배정하고 run 중에는 변경하지 않습니다.

## ADP And Baselines

`simulation_based_adp`는 `mfg_flow_shop / maximize_throughput / worker 3` 전용 event-driven SMDP
정책입니다. 같은 시각의 idle worker와 feasible task를 joint matching으로 구성하고, attention 기반
post-decision value network와 beam search로 행동을 선택합니다.

- 보상: 다음 decision epoch까지 완료된 product 수
- 학습 target: episode 전체의 Monte Carlo return
- loss: MSE
- 미사용 항목: TD, n-step target, bootstrapping, potential shaping
- action: conflict-free task assignment와 선택 가능한 `WAIT`
- rollout: CPU 20-process compact on-policy batch
- network update: main process의 CUDA device
- checkpoint 검증: scenario, objective, worker 수, timing, 설비, buffer, inspection, map 및 feature schema

`random_feasible_dispatch`는 mandatory charging을 먼저 처리하고 각 worker가 `WAIT`와 남아 있는
conflict-free feasible task 중 하나를 균등 무작위로 선택합니다. 이는 ADP와 같은 action contract를
사용하되 학습된 가치함수를 사용하지 않는 기준선입니다.

## Policy Comparison

Worker 3 ADP 비교 profile은 다음 여섯 정책을 동일한 5일 throughput 환경과 held-out seed에서
평가합니다.

1. `random_feasible_dispatch`
2. `immediate_shared`
3. `immediate_dedicated_roles`
4. `rolling_horizon_shared`
5. `rolling_horizon_dedicated_roles`
6. `simulation_based_adp`

Dashboard는 정책별 평균 제품 수, 표준편차, 95% CI, worker 실행비율과 ADP의 seed-paired 차이,
bootstrap CI 및 win/tie/loss를 표시합니다. ADP 우위는 `ADP - Immediate Shared`의 평균이 양수이고
paired 95% CI 하한이 0보다 클 때만 표시합니다.

최신 5-seed 검증 기준의 평균 완료 제품 수는 ADP `45.6`, Immediate Shared `41.0`, Random
Feasible `37.8`, Rolling Shared `30.2`, Immediate Dedicated `30.0`, Rolling Dedicated `27.0`입니다.
ADP와 Immediate Shared의 paired 차이는 평균 `+4.6`개, bootstrap 95% CI `[1.8, 6.8]`이었습니다.
다만 5개 seed 결과는 현재 구성에 대한 예비 실험 근거이며 다른 공정, worker 수 또는 horizon에 대한
일반적 우위를 뜻하지 않습니다.

## Dashboards And Audits

- Training dashboard는 학습·validation 생산량, post-decision value error, WAIT 행동, 행동가치
  rank/Top-1/regret, OOD 선택 및 병렬 rollout/GPU 진단을 표시합니다.
- Policy comparison dashboard는 이론적 상한, 현실적 기대 생산량, 정책 요약 통계와 paired comparison을
  한 화면에서 제공합니다.
- Experiment run은 대용량 `events.jsonl`과 Replay artifact를 기본적으로 저장하지 않습니다. KPI,
  stochastic signature와 Gantt 집계는 유지되므로 정책 성능 비교에는 영향을 주지 않습니다.
- Artifact audit은 queue overflow, reservation leak, task 중복, 역할 위반, battery/inspection 계약,
  collision 및 불연속 이동을 검사합니다.

## Compatibility

- Python 3.12 이상을 권장합니다.
- 기본 규칙 기반 실험은 `requirements.txt`와 sibling HumanoidSim editable install만 필요합니다.
- ADP 학습에는 `requirements-adp.txt`와 CUDA 지원 PyTorch가 필요합니다.
- LLM, OpenClaw, Knowledge Graph와 legacy Streamlit 기능은 선택 의존성이며 정책 비교의 필수 설치가
  아닙니다.
- ADP feature/environment fingerprint가 다른 checkpoint는 fallback 없이 거부됩니다.
